Acceptance Criteria-Based Specification (ATDD & BDD)

Writing requirements using precise test case language before implementation code is produced. Includes ATDD (Acceptance Test-Driven Development) and BDD (Behavior-Driven Development: Given - When - Then).

ATDD BDD

4.3 Acceptance Criteria-Based Specifications

Canonical SWEBOK Text

Acceptance criteria-based specifications directly solve the requirement ambiguity problem because natural languages are ambiguous, but test language is not.

1. ATDD 3-Step Process

  1. Select a unit of functionality (e.g. User Story).
  2. Engineers, domain experts, and QA meet before design/construction to agree on failing acceptance test cases.
  3. Code is written/refactored until all agreed acceptance test cases pass cleanly.

2. BDD Given-When-Then Format

Scenario: ATM Cash Withdrawal
Given account balance is $500 and card is valid,
When Account Holder requests $100,
Then ATM dispenses $100, account balance becomes $400, and card is returned.
