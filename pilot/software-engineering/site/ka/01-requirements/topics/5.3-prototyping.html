Prototyping in Requirements Validation

Building executable UI or architectural prototypes to expose developer interpretation errors, validate dynamic user interaction, and prevent costly downstream rework.

5.3 Prototyping

Canonical SWEBOK Text

When specifications are not directly executable, prototypes demonstrate key dimensions of an implementation, revealing developer interpretation errors early:

Benefits

Better conveys dynamic UI interaction than static text or diagrams; avoids waste caused by implementing wrong requirements.

Risks & Dangers

Cosmetic issues or UI glitches can distract reviewers from validating core underlying business functionality.
