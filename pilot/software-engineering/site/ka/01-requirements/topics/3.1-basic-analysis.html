Basic Requirements Analysis

Requirements analysis evaluates candidate requirements against core desirable properties (unambiguous, testable, binding, atomic, feasible, consistent) and uses the 5-whys technique to uncover true root problems.

3.1 Basic Requirements Analysis

Canonical SWEBOK Text

Desirable properties of individual requirements:

  • Unambiguous: Interpretable in only one way.
  • Testable (Quantified): Compliance or noncompliance can be clearly demonstrated.
  • Binding: Clients are willing to pay for it and unwilling to do without it.
  • Atomic: Represents a single decision.
  • True Stakeholder Needs: Uses stakeholder vocabulary and is acceptable to all.

Desirable Properties of the Overall Collection:

  • Complete: Addresses boundary conditions, exception cases, and security.
  • Concise: No extraneous or redundant content.
  • Internally & Externally Consistent: No conflicts between requirements or source materials.
  • Feasible: Viable within cost, schedule, and staffing constraints.

The 5-Whys Technique

Elicited statements often represent premature solutions rather than the true problem. Repeatedly asking "Why is this the requirement?" strips away implementation assumptions until reaching the fundamental stakeholder need.
